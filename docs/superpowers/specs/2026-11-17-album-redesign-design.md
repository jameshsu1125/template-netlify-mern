# Album 相簿改版設計

日期：2026-11-17

## 目的

現在的 album 用表格一列一張圖，資料夾只能靠「...」回上一層，上傳要切分頁、手打資料夾名稱，一次只能傳一張，刪除確認與批次按鈕分散在頁面上下兩端。使用者覺得「瀏覽找圖」與「上傳整理」兩件事都難用，要一起改善。

## 目標

- 三欄版面：左側資料夾樹、中間縮圖格狀、右側詳細面板（使用者選定：B + C）。
- 上方麵包屑顯示目前位置，可點任一層跳回。
- 上傳到**目前所在的資料夾**，不再手打名稱；支援拖放與按鈕選檔、一次多張。
- 勾選縮圖後才浮出批次操作列（已選 N 張：刪除 / 取消）。
- 點縮圖開右側詳細面板：大圖、尺寸、路徑、開新分頁、複製網址、刪除。
- 在編輯器插圖 Modal 中，面板主按鈕為「插入」。

## 非目標

- 不改後端 API 的路由與回應格式；唯一的後端改動是 Cloudinary 模式的 `search` 補上子資料夾。
- 不支援 Cloudinary 模式刪除資料夾。
- 不做搜尋、排序、標籤、重新命名、搬移檔案。
- 不改圖片壓縮規則（沿用 `CAPTURE_PROPERTY`）。

## 反目標（做了也算失敗）

- 在 Modal 裡擠到無法操作。
- 誤刪：刪除必須經過確認。
- 多張上傳時一張失敗就整批中斷、或看不出哪張失敗。

## 限制

- 後端 `search` 一次只回一層；Cloudinary 模式只回檔案、**不回子資料夾**。
- 上傳一次一張、上限 10MB；壓縮在瀏覽器端（`lesca-react-capture-button`）。
- 必須用 daisyUI 語意色，不寫死色碼；`Tab` 同畫面只能一組，新版不再使用 `Tab`。
- 資料請求只走 `src/hooks/`。

## 做法比較

| 做法 | 取捨 |
| :-- | :-- |
| **1. 展開時才載入（選定）** | 只改前端，點開資料夾時用 `search` 查子層並快取；第一次展開要等一下 |
| 2. 後端新增 `folders` 一次回整棵樹 | 樹一開始就完整，但 BunnyCDN 要逐層遞迴、資料夾多會慢，多一支 API 要維護 |
| 3. 只顯示走過的路徑 | 最簡單，但等於麵包屑，失去資料夾樹的意義 |

## 已決定的設計

### 版面

- 寬螢幕：資料夾樹（約 220px）｜縮圖格狀（自適應欄數）｜詳細面板（約 280px，未選圖時隱藏）。
- 窄螢幕與 Modal 內：資料夾樹收成工具列上的「資料夾」按鈕（點開為下拉或側抽屜）；詳細面板保留。
- 工具列：麵包屑、`＋資料夾`、`上傳`。

### 資料夾樹

- 初始載入根目錄（`'*'`）一層；展開節點時呼叫 `search` 取該資料夾內容，只取 `resource_type === 'folder'` 的項目做子節點，結果快取在相簿元件內部狀態。
- 點節點 = 切換目前資料夾（更新 `context.album.folder`），中間格狀跟著重查。
- 資料夾路徑由前端組成：`父路徑/子資料夾名稱`（不依賴回應中的 `folder` 欄位，因為它可能含 `BUNNY_FOLDER_NAME` 前綴）。
- 上傳、刪除後，重查目前資料夾並使該節點快取失效。

### 縮圖格狀

- 資料夾卡片排前、圖片在後；點資料夾 = 進入。
- 每張圖左上角有勾選框；勾選任一張後，格狀上方浮出批次操作列。
- 單擊圖片開詳細面板；BunnyCDN 回 `width/height = 0` 時沿用瀏覽器端量測。

### 詳細面板

- 大圖、檔名、尺寸、完整路徑。
- 一般模式：`複製網址`（主按鈕）、`開新分頁`、`刪除`。
- 編輯器模式：主按鈕改為 `插入`，行為等同現在的 copy（寫入 `album.copiedText` 並關閉 Modal），由 `tiptab/menu.tsx` 插入。以 `Album` 新增 prop（如 `mode='picker'`）區分。

### 上傳

- 工具列 `上傳` 按鈕選檔（可多選），或把檔案拖到中間格狀區域（拖入時顯示覆蓋提示「上傳到 <目前資料夾>」）。
- 前端排隊逐張上傳（一次一個請求），右下角上傳面板列出每張的狀態：等待 / 上傳中 / 完成 / 失敗（顯示原因，可重試）。
- 全部結束後重查目前資料夾；不再自動切換分頁。
- 上傳期間不開全螢幕 `LoadingProcess`（否則擋住操作），改用上傳面板顯示進度。需要讓 `useUpload` 可選擇不開 Loading。
- `＋資料夾`：輸入名稱後，建立 = 在目前資料夾下以該名稱為目標上傳第一張圖（儲存服務沒有空資料夾）。實作：輸入名稱後直接開啟選檔，上傳到 `目前路徑/新名稱`。

### 刪除

- 單張：詳細面板 `刪除` → daisyUI `modal` 確認框（置中），取代現在頂部的 `Confirm` 橫列。
- 批次：批次操作列 `刪除` → 同一個確認框，列出張數。
- 資料夾：資料夾卡片的選單或樹節點右鍵 / 更多按鈕 → 確認框提示會刪除整個資料夾內容。
- 刪除用的識別值規則不變（勾選 `pixels === 0` 用 `secure_url` 否則 `public_id`；資料夾用結尾 `/` 的 `public_id`）。

### 檔案拆分（建議）

`index.tsx`（容器、版面）、`config.tsx`（內部狀態：選取、詳細面板、樹快取、上傳佇列、確認框）、`tree.tsx`、`breadcrumb.tsx`、`grid.tsx`、`item.tsx`、`detail.tsx`、`uploader.tsx`（拖放與佇列面板）、`confirm.tsx`。移除 `table.tsx`、`tr.tsx`、`list.tsx`、`upload.tsx`。

### Cloudinary 模式（使用者決定：方案 b，小幅改後端）

- 後端 `POST /api/search` 在 Cloudinary 模式，除了原本的 `search` 之外，再呼叫 `cloudinary.v2.api.sub_folders(<目前完整路徑>)`，把每個子資料夾轉成一筆 `TUploadRespond`：`resource_type: 'folder'`、`type: 'folder'`、`filename: name`、`public_id: '<path>/'`，其餘欄位填空值或 0，排在檔案前面。**回應格式不變**，前端兩種模式走同一套邏輯，資料夾樹一律顯示。
- 根目錄 `'*'`：現行程式把 `'*'` 直接接進 expression（`BASE/*`），實作時一併確認根目錄查詢行為；`sub_folders` 對根目錄用 `CLOUDINARY_BASE_FOLDER`。
- `sub_folders` 失敗（例如資料夾不存在）時只回檔案，不讓整個 `search` 失敗。
- **刪除資料夾**：Cloudinary 的 `remove` 用 `uploader.destroy`，刪不了資料夾。本次不支援 Cloudinary 刪資料夾：前端看到 `public_id` 結尾 `/` 且刪除失敗時顯示後端訊息即可；不新增後端刪資料夾功能（非目標）。
- 被否決的方案 a：只在 BunnyCDN 模式顯示資料夾樹。
